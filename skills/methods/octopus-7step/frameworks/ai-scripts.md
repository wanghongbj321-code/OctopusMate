# Octopus 7 步法 · AI 引导剧本

> 适用：`skills/methods/octopus-7step/manifest.yaml` 步骤 01-07。
> 本剧本是 AI 引导层的提问话术参考：读取 manifest 的 question/operations 呈现给顾问，按本剧本组织追问、记录与摘要。
> **AI 铁律（不可违反）**：不从模型/工具/孤立用例推导转型目标；AI 嵌入引导与记录，不替代顾问决策（gate 判定仅作建议）；AI 不设独立主链；只引用顾问确认的共识，访谈/资料降级为背景材料。

## 通用交互规则

1. **开场**：每步先读 manifest `question` 原文向顾问提问，不跳过不缩写
2. **追问分支**：顾问回答模糊/缺失时，用本剧本「追问分支」逐步收敛；仍答不上来 → 登记未决项（T10），不阻塞流程
3. **记录要点**：将顾问回答整理为要点，**回读确认**后再落盘为步骤产出 markdown（共识才可引用）
4. **摘要模板**：每步完成后输出 2-3 行摘要 + 下一步预告
5. **gate 判定**：按 manifest gate 做语义型判定建议（coreCheck 是否满足），结果仅作建议，最终由顾问确认

## 步骤 01 · 界定转型问题与变革必要性

**开场引导**：
> 为了界定这次转型要解决的问题，我先问几个基础问题。第一，为什么必须转型——当前业务价值实现卡在哪里？是客户体验、成本、效率，还是竞争对手已经拉开差距？

**追问分支**：
- 若答"系统/IT 问题" → 追问：「除了系统建设，流程、组织、治理、运营模式上是否有同样需要改变的地方？」（五类缺口）
- 若答"凭感觉" → 追问：「有没有 3-5 项可以量化的绩效基线（成本/周期/效率/体验/收入），当前值与目标或对标差多少？」（P1 证据先于判断）
- 若答"迟早要转" → 追问：「为什么是现在？市场、竞争、监管或技术上有哪些触发因素？延后行动的损失是什么？」

**记录要点**：转型问题陈述 / 量化基线表 / 紧迫性论证 / 问题分级 / 发起人与利益相关者清单。

**摘要模板**：
> 已明确：转型必要性 = {一句话}；量化基线 = {N} 项；问题分级 = {生存/竞争/优化}；发起人 = {姓名}。

---

## 步骤 02 · 明确战略前提、关键取舍与转型边界

**开场引导**：
> 现在把转型的"为什么"和"边界"钉死。转型服务谁、希望形成什么优势？更重要的是——哪些内容**不属于**本轮范围？

**追问分支**：
- 若多个输入混同 → 追问：「哪些是已确认的战略、哪些是领导关注点、哪些是业务诉求？我们分开记录。」
- 级联表每层 → 追问：「这一层你选择什么？**明确不选什么**？」（P1 每层须有"不做什么"）
- 若战略前提无依据 → 追问：「这个前提要成立，需要什么条件（what would have to be true）？证据来源是什么？如果没有，标记待验证。」（T2）

**记录要点**：战略选择级联表（T1）/ 战略前提说明 / 信念假设清单（T2）/ 取舍裁决记录 / 转型边界（含不做什么）。

**摘要模板**：
> 已明确：制胜抱负 = {一句话}；竞争场域 = {选什么/不选什么}；转型边界 = {做/不做}；待验证信念假设 = {N} 条。

---

## 步骤 03 · 拓展未来可能性并推导关键转型变化

**开场引导**：
> 不照搬外部案例的前提下，未来可能状态有哪些？我们先记录外部启发证据，再判断企业需要发生什么变化。

**追问分支**：
- 外部案例 → 追问：「这个案例的证据强度是已规模化验证（S1）、试点验证（S2）还是概念启发（S3）？单一案例不能升行业标准。」（T4）
- 未来不确定 → 追问：「哪两个关键不确定性最影响转型方向？列出高/低两档，我们做 2×2 情景矩阵。」（T3）
- 推导变化 → 追问：「目标业务结果 → 未来运营方式 → 关键能力 → 管理体系 → 技术使能，每一步都能回溯到战略前提吗？」（P1）

**记录要点**：外部启发证据清单（强度分级）/ 情景矩阵（T3）/ 变化对应表 / AI 价值池候选。

**摘要模板**：
> 已明确：情景矩阵 = {2×2 命名}，转型方向在 {≥2} 个情景下成立；关键变化 = {N} 项，均可回溯战略前提。

## 步骤 04 · 构建转型愿景 ★ 核心步骤

**开场引导**：
> 现在把这些输入整合成共同理解的未来状态。先归并 3-5 个未来状态主题——**愿景由共创产生，顾问主持不代笔**（防"咨询公司写、董事会批、邮件发"）。

**追问分支**：
- 主题归并 → 追问：「这些主题合并后，还剩几个？每个主题如何运营、如何创造价值？」
- 价值结果 → 追问：「这个未来状态为客户、员工、业务/组织**创造什么结果与价值**？——愿景不只是状态描述，要落到价值与结果」（对齐愿景口径：状态 + 价值 + 结果）
- 叙事稿 → 追问：「写一页'未来某天的运营场景'故事——那天的客户、员工、决策是怎样的画面？」
- 六特质自检 → 逐项过 T5：可想象/可取/可行/聚焦/灵活/可沟通；**核心判定项：可想象 + 可沟通**——任一"否"回指重做，不登记未决项

**记录要点**：总体转型愿景 / 愿景内涵 / 一页叙事稿 / 共创工作坊记录（≥2 轮）/ 质量自检表（T5）。

**摘要模板**：
> 愿景已成型：{一句话愿景}；六特质自检 = {通过/有条件通过，缺 X 项}；共创 = {N} 轮。

---

## 步骤 05 · 确定转型雄心、变革范围与推进速度

**开场引导**：
> 改变到什么程度、改变哪些对象、以多快速度推进？注意：雄心 = 改变的规模与速度，不是技术方案清单，也不只是业绩目标。

**追问分支**：
- 光谱定位 → 追问：「按流程重构、组织变革、数据/技术架构替换**分别**定位在光谱哪里？不单点拍板。」
- 量化 → 追问：「3-5 项核心 KPI 的现状基线和三年轨迹是什么？暂无法量化的标记'待量化'并登记未决项。」（T6；核心判定项：量化锚）
- 资金 → 追问：「有没有 no-regret moves（短期确定收益的降本提效举措）可以释放资金反哺转型？」（T7）
- 承受力 → 追问：「雄心规模与速度，和资金、人才、时间、管理注意力匹配吗？不匹配就要调整。」（核心判定项：承受力论证）

**记录要点**：雄心草案及决策依据（深度/广度/规模/速度）/ 雄心量化表（T6）/ 速赢资金引擎清单（T7）/ AI 用例组合时间轴（先 lighthouse 后规模化）。

**摘要模板**：
> 已明确：雄心四维 = 深度/广度/规模/速度；量化表 = {N} 项 KPI（{M} 项待量化）；速赢资金引擎 = {N} 个 no-regret 举措。

---

## 步骤 06 · 检验并完善转型愿景与雄心 ★ 最强基座

**开场引导**：
> 愿景与雄心要过五项检验：战略一致性、未来状态完整性、变化必要性、商业价值——还有条件性检验：高管共同承诺。我们逐项过。

**追问分支**：
- 一致性 → 追问：「**删掉所有技术名词后，愿景还有明确的业务方向吗？**」（核心判定项：长期战略一致性）
- 商业价值 → 追问：「每个重大价值来源：服务什么战略选择、改变什么业务结果、影响什么 KPI？指定 value owner。」（核心判定项：商业价值检验）
- 高管承诺（条件适用）→ 追问：「有隐性抗拒吗？处置路径：发起人沟通 → 权责再分配 → CEO 升级 → 激励挂钩。」
- 验证计划 → 追问：「每条待验证假设：验证方式/责任方/时间点？（T8）」

**记录要点**：完善后的愿景与雄心 / 五项检验记录 / 验证计划表（T8）/ 争议与未决条件 / 价值负责人清单。

**摘要模板**：
> 五项检验 = {4 通过 + 1 条件}；验证计划 = {N} 条假设已排期；价值负责人 = {N} 名已指定。

---

## 步骤 07 · 确认转型愿景与雄心

**开场引导**：
> 最后一步：获得甲方正式确认，并具备受控变更能力。先裁决所有未决项（补充/降级/移出），再过 exit criteria。

**追问分支**：
- 未决项裁决 → 逐项三选一：补充回答 / 降级为假设（标注影响面与验证计划）/ 移出范围；**不留无主项**（核心判定项）
- exit criteria → 逐项过 T9：未决项裁决完成 / 关键利益相关者签署 / 资源承诺 / 变更控制规则生效
- 变更控制 → 追问：「触发条件（战略前提变化/外部环境重大变化/检验新证据）、审批人、修订流程是什么？」

**记录要点**：经确认的愿景/雄心/深度/广度/规模/速度 / 确认记录与 exit criteria 判定 / 未决项裁决记录 / 变更控制规则 / 下游接口（能力路线图 / Benefit Case / 沟通策略草案）。

**摘要模板**：
> 确认结论 = {通过/有条件通过}；未决项 = {N} 项已全部裁决（无无主）；exit criteria = {4/4 通过}；下游接口已就绪。

## 出口后（平台层，非方法内）

步骤 07 完成后由平台出口层接管：契约校验（§4 核心字段必填 + validationPlan 条件必填）→ 确认包组装（markdown 唯一事实源）→ 顾问授权（authorized 写入）→ 渲染 HTML（vision-render，默认黑灰专业）。本剧本不覆盖平台层行为。
