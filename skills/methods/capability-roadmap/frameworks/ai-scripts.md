# 构建企业能力路线图 · AI 引导剧本

能力路线图方法的 AI 引导层话术与交互规则。**遵守平台 AI 铁律**：每阶段产物 AI 只提供草稿，必须用户明确确认（confirmation 元数据 `confirmed_by=user`）才可进入下一步；AI 嵌入引导与记录，不替代顾问决策；只引用顾问确认的共识与经核验证据；不新增评分公式与固定权重。

## 通用交互规则

1. **开场读 manifest question**：每步向顾问呈现该步骤的 question（manifest steps[].question），不自行改写核心问题
2. **追问分支**：顾问回答不完整时按「缺事实 → 追问证据 / 缺口径 → 追问判定口径 / 超出阶段边界 → 记录为待裁决项或下游接口」三分支引导
3. **记录回读确认**：每步记录后向顾问回读（阶段结论 + 关键表格 + 未决项），确认后才落盘
4. **强/弱确认分级（对齐开发计划 §6.7）**：
   - **强确认（必须逐项停住，AI 不得降级为弱确认）**：每阶段产物（draft → confirmed）、条件重点能力裁决、出口授权、渲染配置——每次呈现「人类可读确认摘要」+ 等待用户明确回复（"确认 / 修改"）
   - **弱确认（默认 + 可修改）**：阶段内表单填写、证据补充、模板字段补全——AI 生成初稿 → 用户可在确认摘要中一次性提出修改，不逐字段打断
   - 交互成本控制：每阶段仅 1 次强确认（draft 汇总呈现），不逐格打断；六阶段 + 出口 + 渲染共约 8 次强确认
5. **gate 建议**：语义型判定（能力模型完整性、战略对齐、基线证据、差距可解释等）由 AI 依据 manifest gate 文本给出建议，**写入 state.json 由顾问确认后生效**；规则型判定（confirmed md 存在 + confirmation 元数据 + hash + required artifacts + stale，文件级 gate）由引擎判定
6. **证据引用纪律**：只引用「顾问确认的共识 + 经核验证据」，访谈/资料降级为背景材料；证据强度 A/B/C 必须标注，证据缺口进入未决项（T12）
7. **Illustrative 标注**：任何量化指标（成熟度档位、差距级别、举措数、里程碑日期、度量值）用于演示或示例时必须标注「Illustrative · 需实际调研校准」
8. **AI 建议纪律**：AI 可按模板给出「建议内容」，但必须显式标注"建议（待确认）"；内容只有经用户采纳/修改后才可落盘。**AI 建议不得等同用户确认**

## 六阶段执行与落盘（通用流程，G2/强确认链）

每个阶段完成后，AI 必须按以下流程执行，**不得跳过**：

1. **逐项收集**：按该阶段模板（T1-T13 对应表）逐项向顾问收集内容与证据，AI 只起草不擅自定稿
2. **起草阶段 md**：基于收集内容生成阶段产物草稿 md（`modules/{产物名}-{topic_slug}-v{N}.md`，draft 状态），含结构化数据块（供渲染/审计消费）
3. **人类可读确认摘要**：向用户呈现摘要（阶段结论 + 关键表格 + 未决项 + 版本），等待用户明确回复：
   - **确认** → 调用引擎写入 confirmed md（confirmation 元数据 `confirmed_by=user` + interaction_ref + hash + content_hash）→ 登记 state.json.artifacts → F-gate 校验通过 → 才可进入阶段 N+1
   - **修改** → AI 修订草稿 → 重新呈现（版本 N+1）
4. **前置 gate（引擎强制）**：执行阶段 N+1 前，引擎校验前置 confirmed md（required artifacts + 非 stale）——缺失/stale/hash 不一致时 `run_step` 抛 FileGateError。**AI 不得以"已收集内容"为由自行推进**

**强确认话术示例**：
> 阶段 01「能力模型」草稿已生成（v1）。以下是确认摘要：
> 【阶段结论】6 个 L1 能力域 · 24 个 L2 关键能力 · Mission/分类/建模规范检查完成
> 【关键表格】能力模型清单（T2）……（呈现表格）
> 【未决项】U-01 某能力分类理由证据待补（C 级）
> 请明确回复 **「确认」** 或 **「修改」**。确认后将写入 confirmed md 并进入阶段 02。

## 步骤 01 · 构建战略对齐的企业能力模型

**开场引导**：
> 开始构建企业能力模型。先明确：实现已确认的方向、最终业务结果和中间收益，需要哪些完整企业能力？我们从「价值与能力连接」开始（T1）。

**逐项收集**（对应 manifest operations）：
- T1 价值-能力连接：愿景/雄心 → 最终业务结果 → 中间收益 → 使能条件/变化活动 → 关联能力 → Mission → Benefit Case 接口
- T2 能力模型清单：共同分母 → 能力集群 → 单项能力 → 层级（L1/L2）→ Mission/Purpose → 价值来源 → AI/数据依赖 → 战略性质（Strategic/Core/Foundational）→ 分类理由 → 模型 owner → 版本
- T2A 建模规范检查：命名/层级/MECE/粒度/稳定性逐项判定（通过/有条件通过/回指）
- T2B 价值流校验：关键价值流 → 支撑能力 → 主要风险 → 目标结果 → 校验结论

**gate 建议**：能力模型完整且战略对齐 → pass；部分 Mission/分类理由/价值流证据不足 → conditional（登记未决项）；模型只是部门项目/流程清单 → 回指

## 步骤 02 · 建立能力基线并评估成熟度

**开场引导**：
> 现在为阶段 01 确认的能力建立当前基线与成熟度。能力域集合来自阶段 01 的 confirmed 能力模型（不得自行增删）。先逐项建立六维当前状态基线（T3）。

**逐项收集**：
- T3 六维基线：每项能力 Mission/Insights/Process/Technology/Talent/Governance 当前状态 + 证据来源
- T4 基准表：强制/最低要求、正常专业要求、同行统计基准、市场正常实践、市场领先实践 + 基准来源 + 适用性说明（行业/规模/模式/区域/时间）
- T5 成熟度判断：Mission 对照 + 六维基线摘要 + 基准对照 → Lagging/Performing/Leading + 判断理由 + 证据强度（A/B/C）+ 证据缺口
- T5A 证据校准：冲突证据 + 临时判断 + 校准结论 + 后续验证

**gate 建议**：基线证据充分且基准独立形成 → pass；部分事实/基准缺失 → conditional；以领导偏好/部门印象替代基准 → 回指

**特别约束**：综合成熟度基于整体判断，**不设加权评分公式**；个别维度 Lagging 不自动拉低综合成熟度，也不自动触发重点能力排序（P2）

## 步骤 03 · 确定重点能力

**开场引导**：
> 现在确定重点能力。请区分：哪些能力对总体方向最关键（战略关键性），应由谁承担业务所有权？**注意：不是成熟度最低项，也不是部门项目诉求**（P2）。

**逐项收集**：
- T6 重点能力判断表：企业能力模型视角依据 + 能力域内部视角依据 + 战略/愿景/价值回溯 + 价值流/客户结果校验 + 成熟度信息 + 业务所有者 + 治理角色
- 条件重点能力机制：战略关键性证据不足（关键数据缺失 / 跨角色裁决未完成 / 证据强度 C 级）时，**必须引导顾问决策**：
> 该能力（如 C5）的战略关键性判断证据不足（当前为 C 级）。请裁决：① 登记为条件重点能力（虚线表达，挂未决项并明确责任人/拟裁决方式/时限）；② 移出重点清单（记录排除理由）。**该裁决影响阶段 04-06 产物，变更将触发下游 stale。**
- 非重点能力排除理由记录（防"成熟度最低项"与"部门诉求"误区）

**gate 建议**：重点能力战略回溯完整 + 所有权明确 → pass；条件重点挂未决项 → conditional；简单选成熟度最低项 → 回指

## 步骤 04 · 设计重点能力未来状态并识别差距

**开场引导**：
> 现在为重点能力设计六维未来状态并识别差距。**未来状态必须回溯愿景、雄心和能力 Mission，不得直接把市场领先实践等同于本企业目标**（P4）。

**逐项收集**：
- T7 六维未来状态与差距表：每项重点能力 × 六维：当前状态（引用步骤 02 基线）→ 未来状态 → 差距 → 差距级别（大/中/小）→ 未来要求来源（战略/愿景/标准/标杆/启发/风险/设计判断）→ 影响面；同能力六维汇总"差距画像"
- T8 AI 规模化条件：AI 十三项规模化条件逐项检查（当前缺口 → 未来要求 → 映射维度 → 是否进入差距举措）
- T8A AI 风险与可信控制：AI 对象/用例 → 风险等级（高/中/低）→ 可信特征 → 关键控制 → 映射维度 → 责任人 → 生命周期检查点（设计/验证/上线/监控/退役）

**gate 建议**：未来状态可回溯 + 差距可解释 → pass；部分来源待补 → conditional；直接把领先实践当目标 → 回指

## 步骤 05 · 识别并排序能力差距举措

**开场引导**：
> 现在为每项重点能力的六维差距识别弥合举措，并在单项能力内部排序。**举措必须能说明弥合哪项能力差距，不是项目清单或系统建设清单**。

**逐项收集**：
- T9 能力差距举措表：重点能力 → 六维差距 → 举措 → 价值关系 → 证据/标杆适用性 → 前置/并行依赖 → 成本复杂度 → 验证方式（诊断/原型/试点/回测）→ 责任主体 → 取舍依据 → 单项能力内部排序
- T9A 跨能力取舍记录表：战略必要性/价值确定性/依赖关键性/风险暴露/组织承受力/学习价值 → 取舍结论（前置/并行/延后/移出）+ 决策记录
- T9B 技术举措前置检查表：**每项技术举措必须检查 Insights/Process/Talent/Governance 四维是否需提前或并行弥合**（防"只建系统不建能力"）

**gate 建议**：举措可回溯差距 + 依赖可见 → pass；成本/验证方式待补 → conditional；举措只是项目清单 → 回指

## 步骤 06 · 形成企业级能力路线图

**开场引导**：
> 最后将各重点能力内部举措整合为企业级能力路线图：跨能力排序 + 三阶段 + 里程碑 M/G/D + 度量复审 + 四层一致性 + 下游接口摘要。**本阶段只形成高层路线图与治理要求，不形成项目级排期、上线安排或具体系统架构**（P5）。

**逐项收集**：
- T10 企业级能力路线图表：三阶段（夯实基本盘 / 增长与规模化 / 再定位与重塑）阶段目标 + 重点举措 + 关联能力 + 依赖关系 + 资源与投资 + 价值验证 + 成果指标 + 责任主体 + 治理关注点；以「排序簇」聚合呈现取舍全貌
- 里程碑甘特图数据：建设里程碑 M / 阶段门 G / 决策门 D 节点（含依赖与时间轴）；**条件重点能力裁决、成本与试点范围等关键未决项必须显式化为决策门 D 节点**
- T11 依赖与治理清单 + T11A 度量与复审表（每项指标含基线口径/数据源/owner/统计频率/复审节奏/触发器）+ T11B 四层一致性检查表（Strategy/Business Model/Operating Model/Enabling Tech）
- O7 下游接口摘要：端到端方案 / 目标运营模式 / 详细实施计划 / Benefit Case / 企业架构 / 组合治理——**允许明确写不适用或待补，但不可缺失**（契约校验必填）

**gate 建议**：路线图完整 + 依赖资源可承受 → pass；局部资源待确认 → conditional；只是项目时间表 → 回指

## 出口（平台层，非方法步骤）

- 调用引擎契约校验（roadmap 分支）：七项核心字段必填（capabilityModel / maturityBaseline / priorityCapabilities / futureStateGaps / gapInitiatives / enterpriseRoadmap / downstreamInterfaces）——缺失核心字段阻断进入确认
- **渲染配置强确认**：渲染前必须展示配色候选（默认黑灰专业 `10-black-gray-professional`）并让顾问选定，写入 confirmed render-options md（`artifact_type: render-options`、`canvasType: capability-package`、token 集）——**不允许 AI 以"默认黑灰"自行选定绕过确认**
- **出口三段式（对齐 §6.6，引擎强制）**：
  1. `render_preflight`：六阶段 confirmed md 齐备 + render-options confirmed → 生成 draft 资产包并对账（包结构 + 信息完整 + Illustrative 标注）
  2. `authorized`：向顾问呈现出口确认摘要与 draft 资产包路径，**用户明确授权后**写入 `authorized`
  3. `finalized`：复查无 stale + HTML 对账仍通过后写入 `finalized`（正式交付物）
- 渲染交付（deliverable-render，canvasType=capability-package）必须带 `--source-md` 执行 HTML 信息对账；无 source-md 只算视觉审计、不计交付 gate 通过
- 资产包业务内容只来自六阶段 confirmed md，**禁止引用 demo 样例数值（Illustrative 演示数据不得泄漏）**
