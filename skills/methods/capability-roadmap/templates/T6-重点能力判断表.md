# T6 · 重点能力判断表（步骤 03）

> 来源：方法论 v1.2 §5 T6。企业能力模型视角 + 能力域内部视角合并形成企业级重点能力清单。
> 重点能力不是成熟度最低项，也不是部门项目诉求（P2）；战略关键性优先、成熟度仅作补充诊断。

## 条件重点能力机制

当某能力的战略关键性判断证据不足（关键数据缺失 / 跨角色裁决未完成 / 证据强度为 C 级）时，可将其登记为「条件重点能力」：

| 处理 | 说明 |
|---|---|
| 登记 | 列入重点能力清单但标记为条件状态（如虚线表达），记录证据缺口与影响面 |
| 裁决 | 挂未决项（T12），明确责任人、拟裁决方式与时限 |
| 纳入 | 证据补强后确认为重点能力，进入未来状态设计 |
| 移出 | 证据表明非关键差距时移出清单，并记录排除理由 |
| 决策门 | 影响多条价值流的关键条件能力裁决，应作为步骤 06 路线图的决策门节点显式管理 |

## 能力治理角色最小定义

| 角色 | 最小职责 |
|---|---|
| Capability Owner | 对能力目标状态、优先级、收益和跨职能取舍负责 |
| Business Process Owner | 对流程断点、标准化、变体和运营绩效负责 |
| Technology Owner | 对应用、平台、架构约束和技术债治理负责 |
| Data Owner | 对数据定义、质量、权限、血缘和数据风险负责 |
| Change / Talent Owner | 对角色、技能、采用、培训和行为改变负责 |
| Portfolio Governance | 对跨能力优先级、资源冲突、收益跟踪和升级裁决负责 |

## 使用规则

1. 每项能力记录双视角判断依据 + 战略回溯 + 价值流校验 + 成熟度信息（补充诊断）
2. **非重点能力必须记录排除理由**（防"成熟度最低项"与"部门诉求"误区，供步骤 04/05 复核）
3. 条件重点能力按上述机制登记并挂未决项，不静默纳入或移出
