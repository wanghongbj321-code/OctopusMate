# T2A · 能力建模规范检查表（步骤 01）

> 来源：方法论 v1.2 §5 T2A。检查命名、层级、MECE、粒度、稳定性、版本治理，确保能力模型可治理、可复用。
> 三态判定：通过 / 有条件通过 / 回指（核心项失败回指，非核心项登记未决项）。

| 检查项 | 检查问题 | 结论 | 问题说明 | 处理方式 |
|---|---|---|---|---|
| 命名 | 是否避免系统名、部门名、项目名、临时任务名或岗位活动名 | 通过 / 有条件通过 / 回指 | ... | ... |
| 层级 | 是否默认控制在 2-3 层，且下钻有明确决策用途 | 通过 / 有条件通过 / 回指 | ... | ... |
| MECE | 同层能力是否尽量不重叠、不遗漏（相互独立、整体完整） | 通过 / 有条件通过 / 回指 | ... | ... |
| 粒度 | 同层能力颗粒度是否相近（不混企业级能力/流程步骤/个人技能） | 通过 / 有条件通过 / 回指 | ... | ... |
| 稳定性 | 是否不随短期组织、系统或项目变化频繁变化 | 通过 / 有条件通过 / 回指 | ... | ... |
| 版本治理 | 是否记录版本、变更原因、模型 owner、批准人和适用范围 | 通过 / 有条件通过 / 回指 | ... | ... |

## 使用规则

1. 六项逐项检查；结论三选一（通过 / 有条件通过 / 回指）
2. 核心判定项（命名 / 层级 / MECE）失败 → 回指步骤 01 修订能力模型；非核心项（粒度 / 稳定性 / 版本治理）可登记未决项后进入步骤 02
