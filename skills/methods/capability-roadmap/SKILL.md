# 构建企业能力路线图（roadmap-method-capability）

将第一阶段已确认的转型愿景与雄心，转化为战略对齐的企业能力模型（01）、基线与成熟度（02）、重点能力（03）、未来状态与差距（04）、差距举措（05）与企业级能力路线图（06），输出交付资产包（index + 六页）。链接阶段一（转型愿景）与阶段三（端到端解决方案）的枢纽。

## 触发条件

- 顾问选择「构建企业能力路线图」方法发起构建
- 上游：已确认的阶段一愿景与雄心产物（检测到既有愿景/VITAL 产物时提示引用）

## 方法结构

| 步骤 | 名称 | 内容 | 模板 |
|---|---|---|---|
| 01 | 构建战略对齐的企业能力模型 | 价值-能力连接 + 能力清单 + 建模规范 + 价值流校验 | T1/T2/T2A/T2B |
| 02 | 建立能力基线并评估成熟度 | 六维基线 + 基准 + 成熟度 + 证据校准 | T3/T4/T5/T5A |
| 03 | 确定重点能力 | 双视角判断 + 条件重点 + 所有权治理 | T6/T2B 复核 |
| 04 | 设计未来状态并识别差距 | 六维未来 + 差距分级 + AI 条件与风险 | T7/T8/T8A |
| 05 | 识别并排序差距举措 | 举措映射 + 域内排序 + 前置检查 + 取舍 | T9/T9A/T9B |
| 06 | 形成企业级路线图 | 跨能力排序 + 三阶段 + 里程碑 M/G/D + 度量 + 一致性 + O7 | T10/T11/T11A/T11B |
| 出口 | 平台出口（非方法步骤） | 契约校验（roadmap 分支）→ 顾问授权 → deliverable-render 资产包渲染 | — |

## 强确认链（本方法核心约束）

- **每阶段产物 AI 只提供草稿**，必须用户明确确认（confirmation 元数据 `confirmed_by=user`）才可进入下一步
- 文件级 gate（引擎强制）：confirmed md 存在 + confirmation + hash + required artifacts + 非 stale；无有效 confirmed 产物不推进
- 条件重点能力裁决、出口授权、渲染配置均为强确认点；六阶段 + 出口 + 渲染共约 8 次强确认
- 量化指标必须标注「Illustrative · 需实际调研校准」

## 使用

1. 新会话经 roadmap-distill 开场协议收集「项目名称 + Topic」并确认 slug（确认前不落盘）
2. roadmap-distill 调用引擎执行本方法（registry 注册后出现在「选择方法」列表）
3. 出口校验与渲染经平台出口层（roadmap-gate + deliverable-render，canvasType=capability-package）

## 边界

- 本方法只声明六步骤与 gate 判定项；执行由引擎 + AI 引导层承担（AI 引导剧本见 `frameworks/ai-scripts.md`）
- 不新增评分权重、成熟度公式、依赖算法、投资组合模型或阶段门计算规则（方法论 v1.2 规则 4/5）
- 本阶段不形成详细实施计划、项目级排期、上线安排或具体系统架构（P5）
- 交付物业务内容只来自六阶段 confirmed md，**禁止引用 demo 样例数值**（Illustrative 演示数据不得泄漏进交付物）
