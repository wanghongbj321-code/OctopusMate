# VITAL 五维诊断（diagnosis-method-vital）

数据管理域 AI 转型现状诊断方法（对齐 VITAL 方法论设计蓝图；锚点数据见 `frameworks/anchors.md`）。诊断以数据管理平台整体及跨工具业务、数据和技术链路为主要视角，识别阻断性问题并输出诊断报告。

## 触发条件

- 顾问选择「VITAL 五维诊断」方法发起诊断
- 诊断范围：数据管理域纳入范围的平台（职责承接、链路协同、关键问题）

## 方法结构

| 步骤 | 名称 | 内容 |
|---|---|---|
| 00 | 诊断准备 | 范围界定 + 打分规则确认（scoring_config 写入 state.json） |
| 01 | V · 业务价值与战略对齐 | V1-V4 逐角度打分 |
| 02 | I · 数据生命周期与适用性 | I1-I4 逐角度打分（数据链路重点核验） |
| 03 | T · 技术架构与平台支撑 | T1-T3 逐角度打分（接口协同重点核验） |
| 04 | A · 管控、风险与可信保障 | A1-A7 逐角度打分（NIST AI RMF 7 可信特征） |
| 05 | L · 长效运营与持续演进 | L1-L4 逐角度打分 |
| 06 | 阻断性问题与改进路径 | blocker 识别 + 改进路径（阻断优先） |
| 出口 | 平台出口（非方法步骤） | 契约校验（diagnosis 分支）→ 顾问确认授权 → deliverable-render 渲染 |

## 打分规则动态化（D4）

- 锚点数据（`frameworks/anchors.md`）**仅作默认参考**，诊断准备步骤呈现给顾问确认/修改（锚点/步进/阻断阈值）
- 顾问确认后写入 `state.json.scoring_config`（版本化快照），AI 严格按其提示与记录分值
- **禁止**引用锚点数据默认文本作为打分事实（aiConstraints 铁律）

## 使用

1. 新会话经 diagnosis-distill 开场协议收集「项目名称 + Topic」并确认 slug
2. diagnosis-distill 调用引擎执行本方法（registry 注册后出现在「选择方法」列表）
3. 出口校验与渲染经平台出口层（diagnosis-gate + deliverable-render）

## 边界

- 本方法只声明诊断步骤与 gate 判定项；执行由引擎 + AI 引导层承担
- 阻断性问题清单独立呈现，不参与总体分否决（方法论 §二-4）
- 诊断报告不得引用 Demo 样例数值（2.9 分 / <40% / T+15 等）——业务数据只来自确认包
